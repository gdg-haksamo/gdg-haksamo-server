# 학사모 앱 화면·기능 설계 (FE/BE 공통 참고)

기획 이미지 [`학사모.png`](./학사모.png) 와 [`학사모 앱 설계.webp`](./학사모%20앱%20설계.webp) 를 텍스트로 정리한 문서.
디자인 변경이 일어나면 이 문서와 이미지를 동시에 갱신한다.

> **이미지 표기 규칙**
> - **화살표(→)**: 화면 이동을 의미
> - **X 표시**: 해당 기능/요소는 도입하지 않음 (미구현)

## 0. 화면 인벤토리

| 화면 | 진입 경로 | 비고 |
|---|---|---|
| 홈 | 앱 시작 (로그인 후) | 오늘의 추천 + 식당별 메뉴 리스트 |
| 메뉴 상세 | 홈/검색에서 메뉴 클릭 | 영양 정보, 별점 그래프, 리뷰 |
| 검색 | 푸터 검색 탭 | 식당·메뉴 통합 검색 |
| 지도 | 푸터 지도 탭 (후순위) | 그림 지도(5구역), 식당 핀 |
| 공지·이벤트 | 헤더 🔔 아이콘 | 운영자 등록 콘텐츠 |
| 마이페이지 | 푸터 마이페이지 탭 | 키워드/자주 가는 식당/알림 설정 |
| 키워드 수정 모달 | 마이페이지 → 키워드 카드 | |
| 회원가입 (3단계) | 미로그인 진입 | ①이메일 인증 ②기본정보+식당 ③키워드 |
| 로그인 | 미로그인 진입 | |
| 관리자 페이지 | RESTAURANT_ADMIN(자기 식당)/SUPER_ADMIN(전체) | 품절 처리 / 신메뉴 등록 / 이름·가격 수정 (Figma 미설계) |

## 0-1. 비로그인 접근 정책

- **비로그인 공개**: 메인 "오늘의 학식 메뉴 리스트"만 조회 가능.
- **로그인 필요(미로그인 시 안내 + 회원가입 유도)**: 상단 "오늘의 추천 메뉴", 메뉴 상세, 리뷰, 검색 상세, 마이페이지 등.
- BE: 보호 API는 401 `ApiResponse` 반환 → FE가 "로그인 후 이용해주세요" 안내 후 회원가입 화면으로 유도.

## 1. 홈 화면

### 헤더
- 좌: 학교명 ("경북대학교 학식")
- 우: 🔔 아이콘 → **공지·이벤트 페이지** 이동

### 오늘의 추천 메뉴 (메인 카드)
- **비로그인 시**: 카드 대신 "로그인 후 이용 가능" 안내를 노출하고 회원가입으로 유도
- AI(Gemini)가 사용자 선호 기반으로 추천한 메뉴 1건 카드
- 구성:
  1. 메뉴 한줄설명 (AI 생성, `Menu.description` — 신규 메뉴 첫 크롤링 시 미리 생성)
  2. 탄단지·칼로리 (`Menu`의 영양 컬럼)
  3. 식당 이름 및 정보 (짧게)
  4. 리뷰 3개 미리보기 + **리뷰 전체보기** 버튼 → 메뉴 리뷰 상세 페이지
- **새로고침 버튼**: 추천 메뉴 다시 생성 (`Recommendation` row UPDATE), 하루 **최대 3회** 제한
  - 3회 초과 시 "오늘 새로고침 횟수를 모두 사용했습니다" 안내
  - 이전에 추천된 메뉴는 재추천하지 않음 (`excluded_menu_ids`로 중복 방지)
- 카드 클릭 → 메뉴 상세 페이지

### 끼니 토글 (아침 / 중식 / 저녁)
- 현재 시각 기준 default 선택
- BE: 오늘 메뉴는 `MenuSchedule`(date+`time ENUM('BREAKFAST','LUNCH','DINNER')`)로 조회, 메뉴 정보는 `Menu` 조인

### 식당 메뉴 리스트
- 식당 탭: 공식당(학생) / 공식당(교직원) / 복지관 / 정보센터 / 카페테리아 첨성 (5곳)
- 사용자가 **자주 가는 학식당**을 우선 default로 노출
- 각 메뉴: 이름 / 가격 / ★ 리뷰 개수
- 클릭 → 메뉴 상세 페이지
- **하트/좋아요는 도입하지 않음** — 리뷰 개수가 인기 지표

### 푸터 (탭바)
- 홈 / 검색 / 지도 / 마이페이지

---

## 2. 메뉴 상세 페이지

- 메뉴 사진(`Menu.image_url`), 이름, 가격, 식당 정보, 운영 정보(`Restaurant.operating_hour`)
- **AI 한줄 설명** (`Menu.description`) — 신규 메뉴 첫 크롤링 시 Gemini가 미리 생성해 저장 (상세조회 시 실시간 호출 X)
- 영양 정보 (탄·단·지·칼로리 차트, `Menu`의 영양 컬럼 — Gemini 생성)
- **별점 그래프**: 5/4/3/2/1점 분포 막대그래프 + 평균 별점 (예: 4.4)
- 리뷰 리스트
  - 각 리뷰에 **"도움됐어요" 버튼** (1 사용자 = 1 리뷰에 1회)
  - 리뷰별 도움됐어요 카운트 노출
- 리뷰 작성 폼 (별점 1~5 + 텍스트)

---

## 3. 검색

- 검색 대상: **식당명**, **메뉴명**
- 필터: 식당 → 메뉴 순으로 좁히기, 최신순 정렬
- 사용 예: "수육" 검색 → 해당 메뉴 제공 식당 위치가 지도에서 강조 (지도 기능 도입 시)

---

## 4. 지도 (후순위)

- **실제 지도 API는 사용하지 않음** — 학교 그림 지도 (5구역 색상 구분)
- 식당 위치 = 그림 좌표 (`Restaurant.map_x`, `map_y`)
- 핀 클릭 → 해당 식당 홈(메뉴 리스트) 화면으로 리디렉트

---

## 5. 공지·이벤트 페이지

- 헤더 🔔 아이콘으로 진입
- 운영자가 `Event` 테이블에 등록한 공지/이벤트 카드 리스트
- **인스타 등 외부 SNS 연동은 미도입** (X 표시)

## 6. 마이페이지

### 6-1. 프로필 카드
- 닉네임 / 학과(`User.department`) / 학년(`User.grade`)  (예: "컴퓨터학부 / 2학년")
- **본인 리뷰가 받은 "도움됐어요" 누계** (가운데 큰 숫자로 표시)
- 좌우 추가 통계 위젯은 도입하지 않음 (X 표시)

### 6-2. 자주 가는 학식당
- 사용자가 등록한 식당 리스트 (N개)
- 홈 화면 default 노출 식당 결정에 사용
- BE: `FavoriteRestaurant (user_id, restaurant_id)` 복합 PK 테이블

### 6-3. 선호 음식 설정 (키워드 카드 → 키워드 수정 모달)
- 음식 키워드 **고정 칩 선택** (자유 입력 아님, Figma `signin-3`/`my수정` 기준):
  - 맛 취향: 매운 / 순한 / 단 / 신
  - 음식 종류: 면류 / 밥류 / 육류 / 해산물 / 채식 / 국·찌개 / 샐러드 / 빵·샌드위치
  - 요리 종류: 한식 / 중식 / 일식 / 양식
  - 건강 목표: 저칼로리 / 고단백
- 디자인상 **선호(LIKED)만** 수집 (기피 DISLIKED UI 없음). `Preference.type` ENUM은 추후 확장 위해 유지.
- 가입 3단계에서도 동일 칩으로 수집, 마이페이지에서 수정.
- BE: `Preference (user_id, keyword, type ENUM('LIKED','DISLIKED'))`

### 6-4. 알림 설정
| 토글 | 컬럼 |
|---|---|
| 푸시 알림 (마스터) | `push_notification_enabled` |
| 아침 알림 | `notification_breakfast_enabled` |
| 점심 알림 | `notification_lunch_enabled` |
| 저녁 알림 | `notification_dinner_enabled` |
| 이벤트/공지 알림 | `notification_event_enabled` |

마스터 토글이 OFF면 개별 토글 상태와 무관하게 발송 중단.

## 7. 푸시 알림

- 발송 시점 (Figma 기준, 스케줄러): 아침 **07:30** / 점심 **11:30** / 저녁 **17:30**
- 발송 대상 조건:
  1. `push_notification_enabled = TRUE`
  2. 해당 끼니 토글이 `TRUE`
  3. `fcm_token IS NOT NULL`
- 알림 본문: `오늘의 {끼니} 학식 추천: {메뉴명}`
- 푸시 클릭 → 해당 추천 메뉴 상세 페이지로 딥링크
- 발송 기록은 `Notification` 테이블에 저장 (조회 UI는 후순위)

## 8. 회원가입 / 로그인

### 회원가입 흐름 (3단계, Figma `signin-1/2/3`)
1. **이메일 인증 (`signin-1`)** — 이메일 입력 → 인증번호 받기/재전송 → 6자리 입력(유효 **3분** 타이머). 도메인 제한 없음(이메일 *소유* 검증). BE: `POST /api/auth/email/send-code` → `verify-code`
2. **기본 정보 + 식당 (`signin-2`)** — 닉네임(2~8자)·비밀번호·학과(`User.department`)·학년(`User.grade`, 선택) + 자주 가는 식당 복수 선택(`FavoriteRestaurant`)
3. **키워드 선택 (`signin-3`)** — 선호 음식 키워드 복수 선택(`Preference`, type=LIKED), 고정 칩
4. **가입완료** → 자동 로그인 → 홈

> 이메일 인증을 통과한 이메일만 가입 가능(`signup`이 재검증). 키워드를 스킵해도 일반 추천이 동작.
> BE 관점: 현재 `signup`은 `User`(이메일·비번·닉네임·학과)를 생성. `FavoriteRestaurant`(2단계)·`Preference`(3단계)는 Restaurant/Preference 도메인 완성 후 연동.

### 로그인
- 이메일 + 비밀번호
- 응답: **Access Token(JSON 본문 → FE 메모리)** + **Refresh Token(httpOnly 쿠키, 회전)**. 브라우저·탭 종료 후에도 로그인 유지, 만료 시 `POST /api/auth/reissue`로 자동 갱신.

## 7-2. 관리자 페이지 (RESTAURANT_ADMIN=식당 운영자 / SUPER_ADMIN=운영팀)

> 공식당 사장님 미팅 결과 제공 합의. Figma에는 아직 화면이 없어 별도 설계 필요. (출처: `meeting-gongsikdang.md`, 권한 모델은 erd-decisions #27)

- **품절 처리** — 메뉴 옆 [품절] 버튼 클릭 한 번 → `MenuSchedule.is_sold_out` 토글. 다음 끼니·다음 날 자동 "판매중" 복귀(스케줄 wipe). 품절 메뉴는 학생 추천·알림에서 자동 제외.
- **신메뉴 등록** — `Menu` + 당일 `MenuSchedule` 추가
- **이름·가격 수정** — `Menu.name` / `Menu.price` 수정
- 식당 운영자는 **자기 식당만**(`User.managed_restaurant_id`, `RestaurantAdminGuard`로 강제), 운영팀(SUPER_ADMIN)은 전체 + 계정 관리(`/api/admin/**`).
- 로드맵: **2026-07-05 선제공**, **2026-07-10 베타 런칭**

## 9. 도입하지 않는 기능 (기획서 X 표시)
